# ServGo Mail — стратегия продукта: кампании прежде почты

Дата: 13 октября 2026. Статус: согласованное направление, не равнозначно реализованному или развёрнутому функционалу.

## Назначение

**mail.servgo.ru — приватный кабинет владельца платформы ServGo для создания, персонализации, отправки и анализа рекламных email-кампаний.** Обычные входящие/исходящие, ответы и ручная переписка поддерживаются, но являются вспомогательными экранами.

Ключевая ценность — не «отправить N сообщений», а **выявить релевантную потребность конкретной компании, сформулировать полезное предложение, получить заинтересованный ответ и довести диалог до демонстрации или подключения ServGo**.

## Основной сценарий

1. Владелец вставляет email-адреса в поле, загружает CSV/XLSX или добавляет одиночного адресата. **Предварительное создание карточек контактов не требуется**. Система сама создаёт внутренние записи кампании и обнаруживает дубли.
2. Автоматически связывает введённые адреса с известными компаниями, если достаточно подтверждений. Для неопознанных компаний показывает «информации недостаточно», а не выдумывает отрасль или проблему.
3. Исследователь анализирует доступный сайт и предоставленные сведения, сохраняя ссылку на источник и дату проверки. Отдельно отмечает факты, предположения и неподтверждённую информацию.
4. Квалификатор оценивает релевантность ServGo: наличие услуг с записью, потенциальная роль ИИ-маркетинга, понятный следующий шаг; допускает «не подходит» и «нужно уточнить».
5. Копирайтер создаёт **отдельное предложение для каждого адресата**: точная тема, релевантное наблюдение, польза ServGo, короткий CTA и ссылка на подходящую демо-страницу.
6. Критик проверяет достоверность утверждений, правильность имени/сайта/контакта, полезность и нежелательные обещания; инициирует ограниченное исправление действительно существенных ошибок. Итог остаётся на проверке владельца.
7. Владелец видит пакет черновиков, исправляет выборочно, одобряет и запускает кампанию. Требования к основаниям обращения и отписке зависят от соответствующей страны/рынка и режима кампании; нельзя по умолчанию считать все адреса российскими.
8. Очередь отправки соблюдает настройки домена, ограничения почтового провайдера, дедупликацию, отписки, bounce и паузы. Тайм-аут SMTP **не приводит к автоматическому повтору** неизвестно доставленного письма.
9. Входящие ответы сопоставляются с кампанией. Позитивный ответ, просьба не писать и неудачная доставка автоматически отражаются в карточке. Продолжение переговоров — ручное или через предлагаемый, но проверяемый ИИ-ответ.
10. Отчёт по кампании показывает: подготовлено, проверено, отправлено, отклонено SMTP, неизвестный статус, ответы, положительные ответы, заявки/демо. Открытие письма и клики — опционально и только там, где это уместно; не заменяют реальные ответы.

## Первый экран (основная навигация)

1. **Кампании** — активные, подготовка, очередь, завершённые; главный CTA «Новая кампания».
2. **Адресаты** — вставка списка, CSV/XLSX, поиск дублей, статусы, источники, исключения.
3. **ИИ-предложения** — краткие досье компаний, персональные черновики, сравнение правок критика, пакетное рассмотрение.
4. **Ответы** — входящие, ответы по кампаниям, заинтересованные адресаты, предложения ИИ по ответу.
5. **Отправленные** — очереди, доставляемость по SMTP, отказы, история.
6. **Настройки** — адрес отправителя, подпись, подключение IMAP/SMTP, ClaudeHub, график, лимиты и параметры исключения из кампаний.

Обычная кнопка **«Написать»** всегда доступна независимо от базы адресатов: ввод email → тема/текст или помощь ИИ → просмотр → отправить.

## Технические границы

- Код в `grunvald91/booking_bot` совместим с текущей авторизацией ServGo; `Ai_growth_os` содержит наработки ИИ-команды, источников, критика и outreach. Не плодить две независимые модели контактов.
- Доступ только подтверждённому владельцу **всей платформы**; роль владельца чужого бизнеса и клиентский `localStorage.userRole` никогда не дают доступа. Проверять сервером каждую операцию.
- Поддомен `mail.servgo.ru` уже используется SMTP; веб-интерфейс должен добавляться только на HTTPS/443, не затрагивая Postfix, DKIM, SPF, MX или IMAP.
- ClaudeHub API — через серверные переменные окружения. Ключ не попадёт в браузер, логи, GitHub или материалы агента.
- Периодичность отправок **настраивается**, без произвольной привязки к конкретной стране. Однако технические лимиты и обработка жалоб / отписок обязательны для репутации домена.
- Для каждого отправления фиксировать получателя, версию текста, решение владельца, Message-ID, SMTP-результат, время и кампанию. Секреты хранить отдельно.
- Очередь отправки должна быть устойчивой к рестартам (БД, фоновый worker, идемпотентность). Никаких сторонних действий на основании только вывода LLM.
- Входящие письма могут содержать вредоносные инструкции. Их содержание — **данные**, а не команды агенту.
- Метрики должны честно отделять «SMTP принял» от «письмо дошло» и «клиент ответил».

## Приоритет реализации

**P0** — защищённый вход владельца; «Написать» без карточки контакта; список адресатов; персональные черновики; ClaudeHub-критик; ручной просмотр; SMTP; сохранение факта отправки; видимые ошибки.

**P1** — настоящий объект кампании; CSV/XLSX импорт; очередь, расписание, пауза/продолжение; сопоставление ответов из IMAP; антидубли; управление исключениями и bounce; сегментация по специализациям.

**P2** — AI-квалификация и подбор наиболее подходящего предложения, A/B-тесты тем, автоматическая классификация ответов, рекомендации по следующим действиям, CRM-воронка «ответ → встреча → клиент», кампании для других продуктов.

## Состояние на 13 октября

В ветке `feat/owner-mail-console-20261013` уже есть черновая защищённая страница, SMTP/IMAP и простые API для единичных/списочных адресатов, но **кампании как самостоятельная сущность, планировщик, импорт Excel и привязка ответов пока не реализованы**. Ветка не развёрнута; не считать функцию готовой до тестирования с сервером.
