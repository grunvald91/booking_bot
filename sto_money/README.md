# Учёт выручки по бокам СТО — sto.servgo.ru

Страница на поддомене с входом по логину и паролю (Артур, Александр; права одинаковые): календарь по дням,
таблица на 4 бокса (Дмитрий, Алексей, Илья, Сослан), в каждом дне «всего» и разбивка: наличные, на карту
(владельцу, Александру), терминал. Суммы можно править прямо в таблице. Аналитика: итоги, способы оплаты,
рейтинг боксов, график по дням, лучший день, сравнение с прошлым периодом, журнал изменений.

## Как это устроено

- Сервис (`server/`) работает на сервере ServGo, `/opt/sto_money`, порт 127.0.0.1:8095, база SQLite.
  Вход делает nginx (`/etc/nginx/sto_money/htpasswd`) и передаёт имя в `X-Auth-User`.
- Репозиторий публичный, поэтому **данные в нём не хранятся и в Actions не печатаются**. Диктовка уходит
  зашифрованной: файл `sto_money/inbox/*.cms` в ветке `sto-inbox`, шифрование открытым сертификатом
  `keys/entry_cert.pem`, расшифровывает только закрытый ключ на сервере (`/opt/sto_money/keys/inbox_key.pem`).
- Пуш в `sto-inbox` запускает workflow `sto-money-inbox.yml` (скрипт доставки берётся из самой ветки `sto-inbox`; при
  обновлении кода ветку нужно подтянуть к основной): он копирует новые файлы на сервер и применяет их.
  Повторное применение безопасно (имя файла = идентификатор). Ошибка записывается как код (`error bad_box`) и
  не повторяется: нужно отправить исправленную запись новым файлом.
- Выкладка и обновление сервиса: workflow `sto-money-deploy.yml` (сначала `apply=false`, это проверка без изменений).
- Ежедневная копия базы: `/opt/sto_money/backups` (таймер `sto-money-backup.timer`), сама ничего не удаляет.

## Как записать диктовку (для ассистента)

1. Разобрать фразу в операции. Названия боксов только точные: Дмитрий, Алексей, Илья, Сослан (склонения привести
   к имени). Суммы — целые рубли. Дату переводить в ISO (`2026-10-24`) по часовому поясу Москвы; «вчера»,
   «в пятницу» уточнить, если дата неочевидна, и всегда назвать дату в ответе.
   - запись: `{"op":"set","date":"2026-10-24","box":"Дмитрий","total":15000,"cash":5000,"card":6000,"terminal":4000}`;
   - «всего» можно не указывать — тогда оно равно сумме трёх способов оплаты; можно указать только часть полей —
     остальные сохранятся;
   - удаление: `{"op":"delete","date":"2026-10-24","box":"Дмитрий"}`; несколько операций — в одном сообщении.
2. Склонировать ветку `sto-inbox` репозитория `grunvald91/booking_bot` (неглубоко), собрать JSON `{"ops":[...]}` и
   выполнить `python3 sto_money/tools/encrypt_entry.py --inbox sto_money/inbox` (JSON в stdin). Инструмент сам
   проверяет данные и печатает только путь файла.
3. Закоммитить файл с нейтральным сообщением (`inbox: entry`), запушить в `sto-inbox`. **Суммы, имена боксов и
   пароли нельзя писать ни в сообщение коммита, ни в описание, ни в чат-логи Actions.**
4. Дождаться запуска `STO money inbox` (публичный API GitHub: статус и аннотации запуска) и сообщить результат:
   что записано (из продиктованного), либо код ошибки.
5. Расшифровать и прочитать данные ассистент не может и не должен: итоги дня он считает из того, что только что
   продиктовано, а остальное видно на странице.

## Ключ и восстановление

Закрытый ключ шифрования: на сервере и в резервной копии на Google Диске владельца (файл `sto-money-inbox-key.pem`).
Потеряли ключ на сервере: положить копию с Диска в `/opt/sto_money/keys/inbox_key.pem` (через секрет `STO_PRIVATE_KEY`
и workflow выкладки). Потеряли и там и там: создать новую пару (`openssl ecparam` + `openssl req -x509`), заменить
`keys/entry_cert.pem` в репозитории, поставить новый закрытый ключ на сервер. Старые зашифрованные файлы без старого
ключа не прочитать, но данные уже лежат в базе на сервере и в её ежедневных копиях.

## Логины

Логины создаются зашифрованной операцией `set_users` (полный список; пароли не короче 8 символов). Смена пароля —
новая такая запись. Пароли нигде не хранятся в открытом виде.
